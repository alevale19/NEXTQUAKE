README FILEScript_data2FiSH.m reads the inputs reported in the database Fault2SHA Central Apennines Database (version 2020) and coordinates of MainFaults to produce an input file for the matlab codes FiSH (Pace et al., 2016). FISH is a matlab package designed to help seismic-hazard modellers analyse fault data. The output file produced by Script_data2FiSH.m  can be used by the mb.m tool that calculates the global budget of the seismic moment rate.

Note for this script to work, you will need to have the matlab "mapping" toolbox installed.The three matlab files, "script_data2FiSH.m", "deg2utm.m", and "utm2deg.m" should all be placed in the same folder, along with a folder named "INPUT". The two scripts "deg2utm.m" and "utm2deg.m" were written by Rafael Palacios (Universidad Pontificia Comillas, Madrid, Spain) and are used by "script_data2FiSH.m" to convert vectors of UTM coordinates into Lat/Lon vectors (WGS84) and viceversa. Input files have to be placed in the folder INPUT. The inputs are:
(1) Fault2SHA_CentralApennines_Database_2021_v1.xlsx: this is an excel spreadsheet that contains data on the MainFaults, Faults, local geometries and slip rates. The first sheet in "Fault2SHA_CentralApennines_Database_2021_v1.xlsx" contains drop down lists that allow the user to set the desired interpretation of particular MainFaults. Note that the matlab code "script_data2FiSH.m" reads and uses the MainFault options as set in the excel file. Thus, to model different interpretation of these particular MainFaults, the user has to first select the desired alternatives from the drop down lists. (2) MainFaults_lonlat: this is a folder that contains multiple files of coordinates (WGS84) of the MainFaults in a two-columns ascii format.Output files produced by the script are stored in the folders OUTPUT/Table and OUTPUT/Figure. Output files are:
1) An ascii file stored in the folder "Table" that can be used as input for mb.m of FiSH. 2) Figures are stored in the folder "Figures". They show measurement data points, average slip rates and slip rate profiles.Before running the script, the user has to set the following 6 variables in the USER OPTIONS section:1) maxdiffUTM2) Dmax3) extrapolate_slip_rate_option4) outputname5) SeismThick6) ScRmaxdiffUTM  [meters] is an integer that that specifies the maximum difference between two vertexes when resampling the Mainfault traceDmax [meters] is a float number that sets the maximum distance for which a point with slip rate is associated to the Mainfault. extrapolate_slip_rate_option is an integer, 1 or 2: 1 = integral average of a slip rate profile assuming to have a slip rate = 0 at the tips of the Mainfault.2 = arithmetic mean of the slip rate collected along the Mainfault.outputname is a string to input the prefix of the output file name.SeismThick [km] is a float number that defines the seismogenic thickness for all the Mainfaults. This is not given in the CAD, but it is used by FiSH to calculate the area of the MainFault plane.ScR is a string. This is not given in the CAD, but it is used by FiSH to attribute the desired empirical scaling relationship. According to FiSH, allowed codes are: WC94-N, WC94-R, WC94-S, WC94-A, Le10-D, Le10-S, Le10-SCR. For volcanic areas, allowed code is: Az15.We provide two warning messages during the executions of the run: 1) if there are no coordinates of a Mainfault and 2) in case of extrapolate_slip_rate_option =1, in the presence of co-located measurements, the script computes the average of the measurements.
